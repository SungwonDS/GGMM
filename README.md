# GGMM + BIC: 표본에서 새로 적합하는 실험

**`GGMM_BIC.ipynb` 하나만 열어 실행할 수 있습니다.** Colab/Jupyter에서
준비 → 표본 준비 → 새 적합 셀을 실행한 뒤 원하는 실험 셀을 실행하세요.
외부 Python 파일이나 PKL, 내장된 과거 적합 결과를 읽지 않습니다.
노트북에 보이는 저장된 출력은 로컬 검증 실행의 기록이며, 재실행하면 새로 계산합니다.

## 실행과 result

1. **표본 준비**에서 관측값 `X`를 만듭니다. 실제 자료는 X를 해당 열로 바꾸고
   `truth=None`, `SAMPLE_SEED=None`으로 설정하세요.
2. **새 적합** 셀에서 `K_MAX`, 척도 하한, 반복 상한을 지정합니다. 매번 모든 후보를
   새로 적합하여 `result`를 만듭니다. `K_MAX=20`으로 바꾸고 이 셀만 다시 실행하면
   같은 X에서 K=1~20을 새로 탐색합니다. VGM 상한은 `VGM_MAX_COMPONENTS`로 별도 설정합니다.
3. **실험 1~9**는 현재 result만으로 실행할 수 있습니다. 표와 그래프가 같은 셀에 나오며
   다른 실험 셀을 먼저 실행할 필요가 없습니다. VGM·KDE는 해당 비교 셀에서 새로 계산합니다.
4. 성공한 적합들은 메모리의 `runs`에 실행 ID별로 남습니다.
   `list(runs)`로 확인하고 `result = runs[실행_ID]`로 이전 실행을 선택할 수 있습니다.
   새 적합에 실패하면 result는 None으로 남고, 이전 실행은 runs에 유지됩니다.

설정 변수를 바꾸기만 해서는 기존 result가 바뀌지 않습니다. **새 적합 셀을 실행해야 합니다.**
각 실험은 자신이 사용하는 실행 ID·표본 수·K_max를 출력합니다. 이미 표시된 다른 셀의
표·그림은 자동 갱신되지 않으므로 새 결과를 보려면 해당 셀도 다시 실행하세요.
커널을 재시작하면 result와 runs는 사라집니다. 자동 저장·내보내기는 하지 않습니다.

## 실험과 시간

| 셀 | 확인하는 내용 |
|---|---|
| 1 | GGMM 추정식·파라미터, VGM 비교, IAE·ISE |
| 2 | Quantile/Lloyd 출발점, 초기 b, 채택된 시작점 |
| 3 | K별 로그우도·AIC·BIC, 수렴·경계 진단 |
| 4 | 전체 적합, K별 초기화·후보, 시작점별 최적화 시간 |
| 5 | GGMM·전체 표본 KDE·3개 관측값 KDE |
| 6 | 실제 유효 성분 수가 같은 GGMM·VGM |
| 7 | K별 GGMM 밀도·오차와 KDE |
| 8 | 후보를 K<=2로 제한했을 때와 로그우도 최대 K의 실제 곡선·오차·수렴 상태 |
| 9 | 척도 하한이 없는 모형의 무한 우도 반례 |
| 선택 10 | K_max=10·20을 각각 처음부터 적합하는 시간 비교 |
| 선택 11 | 척도 하한별 재적합 |

선택 실험 10·11은 실행 스위치가 기본 False입니다. True로 바꾸면 추가 적합을 실제 수행하며
기본 result를 덮어쓰지 않습니다. 원래 표본에서 측정된 과거 결과를 재사용하지 않습니다.

GGMM의 `fit_seconds`는 초기화부터 모든 K 후보와 BIC 선택까지의 실측 시간입니다.
표본 생성·오차 평가·그림은 제외합니다. K별 누적 시간은 해당 실행의 부분합이며
다른 K_max를 독립 실행한 시간으로 해석하지 않습니다. KDE의 준비 시간과 밀도 평가 비용도
구분합니다. 시간은 컴퓨터·라이브러리·동시 작업에 따라 달라지며 단일 측정입니다.

실험 8은 현재 실행의 K별 적합을 이용합니다. 후보 K=1·2의 초기화와 목적함수는 전체 상한에
의존하지 않으므로 상한을 2로 제한한 선택을 확인할 수 있습니다. 독립 K_max=2 실행시간을
측정한 것으로 표시하지 않습니다. 실험 9는 양의 척도를 계속 줄이는 수학적 반례이며,
하한 없는 최적화가 실제로 그 경로를 따라 수렴했다는 주장이 아닙니다.

현재 추정기는 K_max를 **자동 확장하지 않습니다**. 실험 3에서 선택 K의 상한 도달,
마지막 후보들의 BIC 감소, 상한 후보의 미수렴을 진단합니다. 필요하면 K_MAX를 넓혀 다시
적합하세요. 이 경고가 없더라도 더 큰 K의 BIC가 낮아질 가능성을 배제하지는 못합니다.

## 모형과 해석

흐름은 **X 전체 → K별 결정론적 초기화 → 제한된 수치 우도 최적화 → BIC 최소 → result**입니다.
참 성분 수와 참 밀도는 적합·초기화·선택에 전달하지 않습니다. 참 밀도는 사후 IAE·ISE에만
사용하며 참 밀도가 없는 자료에서는 해당 지표를 계산하지 않습니다.

기본 K_max=10, a 하한=0.001×std(X), 최적화 최대 1500회입니다. b는 양수이고 고정 상한은
없습니다. 수치적으로 표현 불가능한 시도는 거절합니다. 실제 K 후보 상한은 요청값과
표본 수·고유값 수 중 최솟값입니다. 유효한 상수 열은 이 밀도 모형의 적합 대상이 아닙니다.
최적화 미수렴, 우도 감소, 큰 b·척도 하한 접촉을 숨기지 않습니다. BIC는 계산된 국소해
가운데 선택하며 전역 최적해나 참 K 복원을 보장하지 않습니다.

VGM은 sklearn BayesianGaussianMixture, DP prior=0.001, weight>0.005를 유효 성분으로
보고 재정규화합니다. max_iter=1500, n_init=1, seed=27입니다. GGMM과 추정 방법·예산이
다르므로 동일 K만으로 비용이 동일하다고 해석하지 않습니다. KDE는 Gaussian 커널과 Scott
대역폭이며 3-kernel은 전체 표본 중 3개를 뽑습니다(seed=20260914).
로그우도는 적합 표본에서 평가한 값이며 독립 테스트 성능이 아닙니다.
실험 5의 IAE·ISE는 4,000점 사다리꼴 근사, 나머지 비교는 적응적 적분을 사용합니다.
서로 다른 적분법의 마지막 자릿수는 달라질 수 있습니다.

## Python 파일과 개발 검증

- `ggmm_bic_estimator.py`: GGMM 모형·초기화·후보 적합·BIC 선택
- `ggmm_bic_experiment.py`: 새 result 생성과 비교·표·그림
- `test_ggmm_bic_estimator.py`, `test_ggmm_bic_result.py`: 수학·결과 분리·새 적합·시간 검증
- `requirements.txt`: 필요한 패키지

이 Python 파일들은 개발용이며 노트북 실행에는 필요하지 않습니다.
Python 파일로 실행할 때는 같은 폴더에서 다음을 사용합니다.

```bash
python -m pip install -r requirements.txt
python ggmm_bic_experiment.py --n 5000 --kmax 20
python -m unittest test_ggmm_bic_estimator test_ggmm_bic_result
```
